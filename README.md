# Botnet / C2 Traffic Detection Using Machine Learning

A red-team driven research project that builds a controlled C2 beacon, captures its network traffic, and trains an ML classifier to detect it — then stress-tests the detector through systematic evasion.

**Research question:** How robust is an ML classifier that detects C2 beacons based on flow features, and which beacon parameters (jitter, sleep interval, payload size, transport) are most effective at evading it?

---

## Architecture

```
[Beacon Agent (Docker)] ---HTTPS/HTTP---> [Lab C2 Server (Docker)]
          |                                         |
          +------ Capture point (tcpdump/Zeek) -----+
                              |
                    [Feature extraction]
                              |
                    [ML Detector (scikit-learn)]
                              |
              [Evasion variants -> retest loop]
```

Normal traffic is generated by separate containers simulating benign behavior (software updater, REST poller, browser-style HTTP client).

## Quickstart

**Requirements:** Docker, Docker Compose, Python 3.10+

```bash
# 1. Spin up the isolated lab
docker compose up -d

# 2. Start capture
docker exec capture tcpdump -i eth0 -w /captures/session.pcap

# 3. Run the beacon agent
docker exec agent python agent.py --interval 60 --jitter 0.1

# 4. Extract flow features
python features/extract.py --input captures/session.pcap --output data/flows.csv

# 5. Train the detector
jupyter notebook detector/train.ipynb
```

## Datasets

### Public Benchmarks

| Dataset | Purpose |
|---------|---------|
| CIC-IDS2017 | Baseline benchmark — botnet and intrusion detection, direct comparison with published results |
| UNSW-NB15 | Second benchmark — modern attack categories, network flow features |

### Custom Lab Data

Each sample is a labeled flow window (default: 60-second windows, 5-tuple key).

| Label | Source |
|-------|--------|
| `malicious` | Beacon agent (15+ configurations) |
| `benign` | Updater, REST poller, browser simulator |

### Cross-Domain Evaluation

| Train On | Test On | What It Measures |
|----------|---------|-----------------|
| Public (CIC-IDS / UNSW) | Custom C2 | Do published-dataset models catch unseen C2? |
| Custom C2 | Public | Does our lab data generalize to real-world attacks? |
| Both combined | Evasion variants | Does mixing data improve robustness against evasion? |

Features per window: inter-arrival time stats, payload size stats, connection count, bytes up/down ratio, HTTP URI entropy (where available).

See `data/README.md` for the full schema and capture parameters.

## Models

| Model | Notes |
|-------|-------|
| Random Forest | Primary classifier |
| XGBoost | Ensemble comparison |
| Logistic Regression | Linear baseline |
| Z-score (IAT) | Statistical baseline — if ML can't beat this, that's a finding |

Train/test split is by **beacon configuration**, not by row, to prevent leakage between near-identical windows.

## Evasion Techniques Tested

- Jitter randomization (log-normal / Pareto distributions)
- Payload padding (fixed buckets, random size)
- Sleep-wake batching (mimic human user patterns)
- Protocol mimicry (real update-service request shape)
- Combinations of the above

Results are in `evasion/results.md` (populated during Phase 4).

## Ethics and Containment

- All traffic runs inside an isolated Docker network with **no internet route**.
- The beacon sends only harmless heartbeat data (timestamps + random tokens). No command execution, no persistence, no credential access, no real file exfiltration.
- The C2 server logs check-ins only.
- Do not deploy the agent on any machine you do not own.

This project is built for academic research under a signed lab-scope document approved by the department.
